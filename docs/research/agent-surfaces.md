# How a mobile app can be used from chat

Research date: **2026-11-11**; method: open the primary specifications and vendor documentation, distinguish protocol capabilities from each client's availability, and label gaps as unverified rather than infer support. The product target supplied for this review is Wander Fit's **native iOS and Android phone app**; WebMCP is the feature-set lens, whose specification concerns tools supplied by web applications. [WebMCP specification](https://webmachinelearning.github.io/webmcp/)

## Surfaces

### 1. A remote MCP server hosted by the app team

**What it is.** An MCP server is separate from the chat host and provides tools and context; a remote server can accept multiple clients through a network endpoint using **Streamable HTTP**. [MCP architecture](https://modelcontextprotocol.io/docs/learn/architecture), [Streamable HTTP](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)

**What the person needs; phone use.** MCP itself defines a protocol, not a consumer subscription or phone application; the person needs a compatible chat client and whatever account access the connected service requires. [MCP architecture](https://modelcontextprotocol.io/docs/learn/architecture), [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) A person can use a remote connector from **Claude on both iOS and Android**. [Claude mobile connector availability](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities) See section 2 for ChatGPT's distinct plugin and custom-server paths.

**Reads and writes.** The protocol names discovery **“tools/list”** and invocation **“tools/call”**; tool handlers can query data or perform operations against external systems. [MCP tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) Resources are a separate, optional context mechanism: **“resources/list”**, **“resources/read”**, and URI templates expose application information, with presentation and context inclusion controlled by the host. [MCP resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources)

**Authentication.** HTTP authorization uses an OAuth 2.1-based contract: the MCP server is a resource server, the chat client is an OAuth client, and an authorization server issues access tokens; protected-resource metadata supports discovery, and tokens must be validated for the intended resource. [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization) OpenAI documents OAuth 2.1 for authenticated plugin servers, while Claude also documents fixed-credential headers, with limited beta availability for that alternative. [OpenAI authentication](https://developers.openai.com/plugins/build/auth), [Claude authentication options](https://claude.com/docs/connectors/custom/add-unlisted.md)

**Can one server serve multiple chat vendors? Yes, subject to compatibility.** Both OpenAI and Anthropic accept team-hosted remote MCP endpoints, so a shared endpoint is possible rather than a separate server mandated by each vendor. [OpenAI connection guide](https://developers.openai.com/plugins/deploy/connect-chatgpt), [Claude server guide](https://claude.com/docs/connectors/building) This does not promise every MCP feature in every client: Claude documents a supported subset, and the July 2026 transport revision explicitly requires backward-compatibility handling. [Claude supported features](https://claude.com/docs/connectors/building), [MCP transport compatibility](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http)

**Can chat show actual app values? Yes.** If an authorized tool retrieves today's workout, calendar entries, or an intake answer, that application-produced value can be returned through **“structuredContent”**, optionally constrained by **“outputSchema”**, and/or through **“content”** blocks; these are server results, distinct from model-generated structured outputs. [MCP structured tool results](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) OpenAI explicitly places `structuredContent` and `content` in the conversation transcript and makes them available to the model and optional component. [OpenAI tool-result reference](https://developers.openai.com/plugins/reference)

**Can a write wait for confirmation inside chat? Yes, with client support.** MCP's tool interaction guidance recommends human confirmation but does not mandate one universal UI. [MCP tool interaction model](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) The protocol mechanism **“Elicitation”**, specifically **“elicitation/create”** in **“form”** mode, collects user input inside a supporting client and returns **“accept”**, **“decline”**, or **“cancel”**; a server can use that response before completing a write, but the client must advertise the relevant capability. [MCP elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation) In the current revision this input request can be carried by `InputRequiredResult`; URL-mode elicitation instead sends the person outside the chat for the interaction. [MCP elicitation messages](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation) This protocol facility is separate from the ChatGPT and Claude approval controls described below; their existence does not establish that every mobile client implements server-requested elicitation. [MCP elicitation capabilities](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation), [ChatGPT permissions](https://help.openai.com/en/articles/20001495-managing-app-permissions-in-chatgpt), [Claude tool permissions](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)

### 2. ChatGPT plugins, connected apps, and custom MCP connections

**Current names and implementation.** The current developer documentation calls the package a **plugin**, the service connection a **connected app**, and the custom-server flow **Add custom MCP server → Create as a plugin**; the custom-server guide says Developer Mode no longer needs to be enabled first. [ChatGPT plugin terminology](https://learn.chatgpt.com/docs/plugins), [Connected apps](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt), [Custom MCP setup](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt) For live data and controlled actions, the mobile-app team exposes an MCP server; an optional web component renders in a ChatGPT iframe, rather than ChatGPT loading an Expo/React Native binary. [OpenAI server guide](https://developers.openai.com/plugins/build/mcp-server), [MCP server and UI quickstart](https://developers.openai.com/plugins/build/app-quickstart)

**What the person already needs to pay for.** There are two different documented access paths: the plugin directory exists across ChatGPT plans, with individual plugin access dependent on plan, region, workspace, role, and capabilities; that is not a guarantee that any particular plugin is free. [Plugin availability](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt) For **custom-server full MCP support**, the specific help page names **Business and Enterprise/Edu**, on the web, and says **Pro** can connect custom servers with read/fetch permissions; that page does not establish Plus, Free, or Go entitlement to arbitrary custom-server writes. [Custom MCP plan requirements and FAQ](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt) The person also needs the provider account or workspace connection that is authorized to access the relevant data. [Connected-account requirements](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt)

**Reads, writes, results, and confirmation.** Custom MCP tools support reads and writes, and ordinary tool use does not require the special `search`/`fetch` pair used by company-knowledge workflows. [OpenAI custom-server guide](https://developers.openai.com/api/docs/guides/custom-mcp-server) Tool values can reach the conversation through `structuredContent` and `content`; a custom UI is optional. [OpenAI result reference](https://developers.openai.com/plugins/reference), [OpenAI server guide](https://developers.openai.com/plugins/build/mcp-server) The named client setting **“Allow read actions”** permits reads while asking before changes, while **“Always ask”** asks before both; approval cards can offer **“Allow once”** or denial, and other permission modes can permit actions without repeated prompts. [ChatGPT app permissions](https://help.openai.com/en/articles/20001495-managing-app-permissions-in-chatgpt) The annotation **“destructiveHint”** informs approval behavior but does not replace server authorization. [OpenAI annotations](https://developers.openai.com/plugins/reference)

**iOS and Android.** General plugins are documented for ChatGPT mobile, and the connected-app guide explicitly covers iOS and Android interfaces; plugins marked Desktop only are excluded. [Plugin surfaces](https://learn.chatgpt.com/docs/plugins), [Mobile connected-app terminology](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt) However, the custom-MCP help page scopes full support to **ChatGPT web** and says adding custom servers on mobile is unavailable; universal iOS/Android read-and-write use of an arbitrary private custom server is therefore **unverified**, rather than established by the broader plugin statement. [Custom MCP availability and mobile FAQ](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt), [General mobile plugin support](https://learn.chatgpt.com/docs/plugins)

### 3. Claude connectors and custom connectors

**What it is; same server as section 1.** Claude's connector is its client-facing connection to an MCP server; a custom connector accepts a server URL, while a directory connector has a listing, and both use the same connector infrastructure. [Claude server and distribution guide](https://claude.com/docs/connectors/building) Consequently, it can use the same compatible remote server as another MCP client; even optional MCP Apps UI can share one codebase across supporting hosts, with host-specific configuration. [Claude cross-host MCP Apps guidance](https://claude.com/docs/connectors/building/mcp-apps/getting-started)

**Account, subscription, and authentication.** Custom connectors are available on **Free, Pro, Max, Ultra, Team, and Enterprise**; Free permits one custom connector, so a paid Claude subscription is not required for that one connection. [Claude custom-connector plans](https://claude.com/docs/connectors/custom/add-unlisted.md) Users can sign in through the server's OAuth flow; supported client-identity options include published client metadata, dynamic registration, and a pre-registered client, while fixed-header credentials have limited beta access. [Claude authentication settings](https://claude.com/docs/connectors/custom/add-unlisted.md)

**Reads, writes, results, and confirmation.** Remote tools can read, create, modify, and delete application data within the granted access. [Claude tool actions](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) Claude documents tools and resources, including text/image tool results, but excludes resource subscriptions from its supported subset. [Claude MCP feature support](https://claude.com/docs/connectors/building) Its UI example returns `structuredContent` for rendering alongside text content, demonstrating that an app-produced value can become a displayed result. [Claude structured-result example](https://claude.com/docs/connectors/building/mcp-apps/quickstart) Tool approvals exist, and **“Needs approval”** is a documented permission alongside **“Always allow”** and **“Blocked”**; standing approval means confirmation is not inevitable for every write. [Claude approval requests](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), [Claude tool permissions](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)

**iOS and Android.** Remote connectors work on both; once connected through web or desktop, they are available in the same account on either phone platform, while mobile installation is described as beta and web/desktop remain the primary custom-connector setup path. [Claude phone setup and use](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities) Requests reach the server from Anthropic's infrastructure, including when the person is using a phone. [Claude remote-server networking](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) Interactive connectors also have iOS/Android support, but the side panel, full-site views, and navigation pinning are not yet on mobile. [Claude interactive mobile limits](https://support.claude.com/en/articles/13454812-use-interactive-connectors-in-claude)

### 4. WebMCP as the reference surface

**Whose specification; what it attaches to.** WebMCP is published by the **W3C Web Machine Learning Community Group** as a draft report, explicitly outside the W3C Standards Track. [WebMCP status](https://webmachinelearning.github.io/webmcp/) Its API attaches to a web **Document**, through **`document.modelContext`**, in a secure Window context. [WebMCP API](https://webmachinelearning.github.io/webmcp/)

**Actual feature set.** Page JavaScript uses `registerTool()`, `getTools()`, and `executeTool()` for registration, discovery, and invocation, with descriptions, input/output schemas, JSON-serialized results, tool-change events, and cancellation. [WebMCP project explainer](https://github.com/webmachinelearning/webmcp/blob/main/README.md) Browser-agent page observations are implementation-defined, with non-normative examples including screenshots and accessibility information; this is not a standardized native screen-state reader. [WebMCP page observations](https://webmachinelearning.github.io/webmcp/) The current annotation **“consequentialHint”** identifies consequential actions, but the current API has no `requestUserInteraction()` confirmation method; actual confirmation remains an agent/browser or application UI responsibility. [WebMCP API and security model](https://webmachinelearning.github.io/webmcp/), [Chrome confirmation guidance](https://developer.chrome.com/docs/modern-web-guidance/guides/webmcp/webmcp)

**Prerequisites and native availability.** Chrome's documentation still describes an experimental browser feature and identifies Tools support, without MCP Resources or Prompts; browser/agent availability is required, rather than a WebMCP consumer subscription. [Chrome implementation guidance](https://developer.chrome.com/docs/modern-web-guidance/guides/webmcp/webmcp) React Native renders native views; WebMCP inside either native app or an embedded WebView is **unverified** by the opened primary docs. [React Native components](https://reactnative.dev/docs/intro-react-native-components), [WebMCP API scope](https://webmachinelearning.github.io/webmcp/)

**Expo web is a separate case.** Expo's web target renders browser content through React DOM/React Native for Web, making a browser-hosted build a possible WebMCP surface where the browser implements it; this says nothing about WebMCP availability in the native binaries or universal mobile-browser support. [Expo web target](https://docs.expo.dev/workflow/web/), [Chrome implementation status](https://developer.chrome.com/docs/modern-web-guidance/guides/webmcp/webmcp)

### 5. On-device assistants: Apple App Intents and Android APIs

**Apple: native actions and data.** App Intents makes app actions available to Siri, Shortcuts, and other system experiences; `AppIntent` and `AppShortcutsProvider` are available from **iOS 16**. [AppIntent platform availability](https://developer.apple.com/documentation/appintents/appintent.md), [App Shortcuts availability](https://developer.apple.com/documentation/appintents/appshortcutsprovider.md) The person needs an app implementing those actions and the relevant system experience; the API documentation does not specify a paid ChatGPT/Claude account prerequisite or a separate App Intents subscription. [App Intents overview](https://developer.apple.com/documentation/appintents/getting-started-with-the-app-intents-framework.md) App entities and queries expose selected app data, intents execute app code, and snippets can display results; **“ReturnsValue”** delivers a value to the initiator. [App Intents data and presentation](https://developer.apple.com/documentation/appintents/getting-started-with-the-app-intents-framework.md), [ReturnsValue](https://developer.apple.com/documentation/appintents/returnsvalue.md) **“requestConfirmation()”** prompts before an intent proceeds, returning normally on confirmation and throwing on cancellation. [Apple confirmation API](https://developer.apple.com/documentation/appintents/appintent/requestconfirmation().md)

**Android: AppFunctions is a first-party equivalent, with rollout limits.** Google's **AppFunctions** platform API and Jetpack library let authorized callers discover and execute app functionality locally, on **Android 16 or higher**, with the **`EXECUTE_APP_FUNCTIONS`** permission. [Android AppFunctions overview](https://developer.android.com/ai/appfunctions) The opened overview still labels the feature experimental, describes Gemini integration as a private preview, and limits the complete pipeline to selected apps/agents; it does not establish general production access or a production subscription entitlement. [AppFunctions availability and FAQ](https://developer.android.com/ai/appfunctions) The Jetpack library separately reached **1.0.0-rc01 on November 4, 2026**; SDK release status alone does not resolve those end-to-end availability restrictions. [Jetpack releases](https://developer.android.com/jetpack/androidx/releases/appfunctions), [AppFunctions FAQ](https://developer.android.com/ai/appfunctions)

Functions can read or change app data and return serializable response types; Google's examples create and retrieve tasks, while its guidelines also demonstrate updates. [AppFunctions implementation](https://developer.android.com/ai/appfunctions/add-appfunctions), [AppFunctions update example](https://developer.android.com/ai/appfunctions/quality-guidelines) For destructive actions, the integration guide calls for the **app's own confirmation step**; it does not document a universal assistant-chat confirmation API equivalent to Apple's method. [Android confirmation guidance](https://developer.android.com/ai/appfunctions/add-appfunctions)

**Android also documents App Actions.** Google Assistant App Actions maps predefined built-in intents to an installed app's features and can show widgets for answers or simple confirmations; that is a narrower documented voice/action surface than arbitrary MCP tools. [Google Assistant App Actions](https://developer.android.com/develop/devices/assistant/overview) This guide establishes an Android integration, not iOS support or automatic compatibility with Gemini AppFunctions. [App Actions](https://developer.android.com/develop/devices/assistant/overview), [AppFunctions](https://developer.android.com/ai/appfunctions)

**What native integrations add, and their cross-platform boundary.** Apple intents can run in an app or extension, foreground/background, and use donated on-screen entities; Android AppFunctions can use existing on-device app state without a separate service. [Apple execution and contextual entities](https://developer.apple.com/documentation/appintents/getting-started-with-the-app-intents-framework.md), [Android local-state comparison](https://developer.android.com/ai/appfunctions) A remote MCP endpoint alone has no documented route into that installed-app execution context; access to server data does not automatically grant these OS integrations. [MCP remote architecture](https://modelcontextprotocol.io/docs/learn/architecture), [Apple native execution](https://developer.apple.com/documentation/appintents/appintent.md), [Android local-state comparison](https://developer.android.com/ai/appfunctions) App Intents provides the Apple half and AppFunctions/App Actions the Android half; none of these APIs is one native assistant surface for both phone platforms. [Apple platform availability](https://developer.apple.com/documentation/appintents/appintent.md), [Android API scope](https://developer.android.com/ai/appfunctions), [Android App Actions](https://developer.android.com/develop/devices/assistant/overview)

## What this rules out

- **Treating the Expo web build as proof of native WebMCP support:** the web build uses DOM primitives, while native React Native uses platform views, and WebMCP specifies a Document API. [Expo web](https://docs.expo.dev/workflow/web/), [React Native](https://reactnative.dev/docs/intro-react-native-components), [WebMCP](https://webmachinelearning.github.io/webmcp/)
- **Assuming an MCP server reads whatever is on the athlete's phone:** resources/tools expose selected information, while remote calls bypass the app's local UI context. [MCP resources](https://modelcontextprotocol.io/specification/2026-07-28/server/resources), [WebMCP's remote/page comparison](https://github.com/webmachinelearning/webmcp/blob/main/README.md)
- **Equating a ChatGPT directory plugin with unrestricted private custom-MCP access:** the specific custom-server document imposes paid-workspace/web limits, despite general mobile plugin support. [Custom-server requirements](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt), [Mobile plugins](https://learn.chatgpt.com/docs/plugins)
- **Treating OAuth consent or a safety annotation as confirmation of every write:** OAuth grants access, annotations inform the client, and ChatGPT/Claude permission settings can allow actions without a fresh prompt. [MCP authorization](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization), [OpenAI annotations](https://developers.openai.com/plugins/reference), [ChatGPT permissions](https://help.openai.com/en/articles/20001495-managing-app-permissions-in-chatgpt), [Claude approvals](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
- **Claiming one generally available on-device assistant API covers both platforms:** Apple and Android expose different native frameworks, and Android's complete AppFunctions/Gemini pipeline remains preview-gated in the opened overview. [Apple AppIntent](https://developer.apple.com/documentation/appintents/appintent.md), [Android AppFunctions](https://developer.android.com/ai/appfunctions)
- **Equating native execution with wholly on-device AI processing:** Google's integration guide explicitly allows system agents to process user queries on servers. [Android processing guidance](https://developer.android.com/ai/appfunctions/add-appfunctions)
